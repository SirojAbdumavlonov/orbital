# Orbital — context for Claude Code

Orbital (working name) is a macOS desktop app for managing Linux servers over SSH: an SFTP file browser, a Monaco editor with "safe save" for config files, systemd services, Docker containers, agentless metrics, an embedded PTY terminal and a tamper-evident audit log. The goal is a product Sirojiddin can promote as a startup. Competitors: Termius and Royal TSX (Cyberduck only overlaps on SFTP).

## Architecture
- `crates/orbital-core/`: the Rust engine, with no UI dependency. `Engine` (engine.rs) is the single entry point, and **every state-changing operation must go through it and record an audit event**.
  - ssh.rs: connect (directly or along a jump-host route, `connect_route`), host-key check (TOFU pinning plus ~/.ssh/known_hosts), auth (password with keyboard-interactive fallback, key, agent), exec, `exec_privileged` (sudo; the password goes over stdin, never argv), `exec_inspect` (read-only: root if sudo works, else the login user), `exec_privileged_with` (extra stdin after the sudo password line, e.g. for chpasswd, and a custom timeout for long dumps)
  - filetools.rs (Files tab: `find_command`/`parse_find` (portable find, `MAX_FOUND` 200), `tar_command` + `SshSession::download_folder` (tar czf - streamed into a local file, progress, cancellable); incl. `upload_tree` for folders and `copy_to` for server-to-server copies), config_edit.rs (stage → pre-validate → backup → `cat tmp > file` → post-validate → rollback; `read_backup` only reads `<file>.orbital-bak-<digits>` (`is_backup_of`), and `Engine::restore_backup` puts one back through safe save), services.rs (systemd plus pre-flight checks), docker.rs (docker CLI JSON with sudo fallback; `create_script`, `change_script`, `lockout_reason`), cron.rs (jobs from crontabs and /etc/cron.d, `describe`, `next_runs`, `apply` for crontab changes keyed by the exact line, `run_now_command`), usage.rs (disk usage one level at a time via `du`, CPU per process from two /proc samples a second apart, grouped by program/service/user), sysinfo.rs (Monitor's server details, read once per visit), tools.rs (software detection: fixed `CATALOG` → one sh script → `DetectedTool`s; ## Rules
- Sudo fallback: an action refused as the login user is retried with sudo when the profile allows elevation (`sftp::denied`, `deploy::refused`/`deploy::as_root`, `docker::is_socket_denied`); reads use `exec_inspect`. Arbitrary user commands (snippets, run_command) are never re-run automatically: they set `needs_sudo` and the UI offers "Run again with sudo".
- The app was called Outpost until 2026-11-15. The old name stays on purpose for migrating users: `OLD_HOMES` in `src-tauri/src/lib.rs` (moves the database from `app.outpost.desktop` / `app.orbital.desktop` into `.orbital`) and `.outpost-bak-*` in `config_edit::list_backups`. Don't rename those.
- Any value interpolated into a remote command must go through `shell::quote`. Identifiers (unit and container names) must also pass `validate_unit` / `validate_container`.
- Secrets never go into SQLite, logs or the audit trail, and never into the Keychain: they go to the vault (`VaultStore`), which must not prompt the user.
- Saved credentials are read only through the engine's `GatedStore`, never the raw store. Any new code path that reads one must first obtain an `Unlock` via `Engine::unlock_for`, and `ssh::saved_secrets_wanted` must stay in sync with the reads in `SshSession::authenticate`.
- A host-key fingerprint is pinned only for the endpoint the user confirmed it for (`ConnectOptions::accept_host`), and a typed secret is used only for the profile it was typed for. A jump-host route never falls back to a direct connection.
- The tool-detection script is built only from `tools::CATALOG`; never interpolate user or server data into it. Tool views don't write configs themselves: edits go through the editor and safe save.
- Anything that can lock the user out (firewall rules, turning ufw on, bans, sshd) needs an engine-side pre-flight check that fails with `PreflightFailed`; the UI may only override it with `force` after a typed confirmation. ufw deletes go by number only after `verify_refs` matched the rule text. Banning the connection's own address is refused with no override.
- Users' crontabs change only through `crontab -u USER -` (it validates), and only after `cron::apply` found the exact line being changed. "Run now" runs only commands that are in a crontab. System cron files are edited in the editor.
- Secrets for the server (new user passwords) go over stdin via `exec_privileged_with`, never into a script or argv; scripts are what gets audited.
- New engine features need unit tests. Anything that touches a server needs a case in `crates/orbital-core/tests/live_ssh.rs`.
- The UI style is slate-blue graphite with a single amber accent (`--amber`), used only for primary actions, selection and live signal. IBM Plex Sans for the UI; JetBrains Mono only for paths, commands, code and the terminal.

## Commands
- `npm install`, `npm run tauri dev` (the app), `npm run demo` (UI with mock data at :1430)
- `cargo test -p orbital-core`, `cargo clippy -p orbital-core --all-targets -- -D warnings`
- `npm run typecheck`, `npm test`, `npm run build`
- Releases: `npm run release -- patch|minor|major|beta|X.Y.Z` (bumps every version, dates `## Unreleased` in CHANGELOG, commits, tags), push the tag, publish the draft. See docs/RELEASING.md
- Live storage tests: `bash scripts/it-storage.sh`, export what it prints, `cargo test -p orbital-core --test live_storage -- --test-threads=1`, then `bash scripts/it-storage.sh stop`
- Live SSH tests: `sudo bash scripts/it-sshd.sh` on Linux/CI, export the printed vars, then `cargo test -p orbital-core --test live_ssh -- --test-threads=1`
