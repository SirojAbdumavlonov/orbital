# Orbital — context for Claude Code

Orbital (working name) is a macOS desktop app for managing Linux servers over SSH: an SFTP file browser, a Monaco editor with "safe save" for config files, systemd services, Docker containers, agentless metrics, an embedded PTY terminal and a tamper-evident audit log. The goal is a product Sirojiddin can promote as a startup. Competitors: Termius and Royal TSX (Cyberduck only overlaps on SFTP).

## Architecture
- `crates/orbital-core/`: the Rust engine, with no UI dependency. `Engine` (engine.rs) is the single entry point, and **every state-changing operation must go through it and record an audit event**.
  - ssh.rs: connect (directly or along a jump-host route, `connect_route`), host-key check (TOFU pinning plus ~/.ssh/known_hosts), auth (password with keyboard-interactive fallback, key, agent), exec, `exec_privileged` (sudo; the password goes over stdin, never argv), `exec_inspect` (read-only: root if sudo works, else the login user), `exec_privileged_with` (extra stdin after the sudo password line, e.g. for chpasswd, and a custom timeout for long dumps)
  - sftp.rs (incl. `upload_tree` for folders and `copy_to` for server-to-server copies), config_edit.rs (stage → pre-validate → backup → `cat tmp > file` → post-validate → rollback), services.rs (systemd plus pre-flight checks), docker.rs (docker CLI JSON with sudo fallback; `compose_args` builds `docker compose -p -f … up -d|restart|pull` from the container's labels), metrics.rs (one /proc script, parsed locally), databases.rs (PostgreSQL/MySQL/MongoDB list and `backup_script`, Redis INFO and actions), webservers.rs (Apache `-S`/`-M`/sites, HAProxy cfg + stats socket), users.rs (accounts; `create_script`, `change_script`, `lockout_reason`), cron.rs (jobs from crontabs and /etc/cron.d, `describe`, `next_runs`, `apply` for crontab changes keyed by the exact line, `run_now_command`), usage.rs (disk usage one level at a time via `du`, CPU per process from two /proc samples a second apart, grouped by program/service/user), sysinfo.rs (Monitor's server details, read once per visit), tools.rs (software detection: fixed `CATALOG` → one sh script → `DetectedTool`s), nginx.rs (read-only parser of `nginx -T` into sites, upstreams and files), firewall.rs (ufw: parse status, `rule_args` builds commands, `ssh_reachable` lockout check), fail2ban.rs, certbot.rs, dns.rs (Cloudflare API client with our own validation, `dns_accounts` table, tokens in the vault under `dns:<id>:token` (gated like `profile:`), DoH checks against public resolvers, `is_public`), sshd.rs (`sshd -T` review), ports.rs (`ss`/`lsof` plus ufw verdict), storage/ (FTP/FTPS via suppaftp, WebDAV via reqwest + roxmltree, S3 with our own SigV4 in s3.rs; `StorageSession` behind the same file calls; the engine keeps these in `storage` beside `sessions`, and `Engine::session` refuses SSH-only calls on them with InvalidInput), streams.rs (`open_stream`: a command whose output streams to the UI; `sudo_works`), tunnels.rs (local port forwarding over `direct-tcpip`, 127.0.0.1 only), logs.rs (`follow_command` for files, journals, containers), deploy.rs (apps and deploy history in SQLite; fast-forward-only update, build, restart, rollback; `inspect_script`/`parse_checkout`), terminal.rs (PTY channels; root shells via `shell_command` + `PromptFilter`, which hides sudo's marker prompt and answers it with the saved sudo password; `InputGate` holds keys typed before sudo accepted it, so they aren't read as the password, and `redact` strips the password from output as a last guard), audit.rs (append-only and SHA-256 hash-chained), known_hosts.rs, profiles.rs (incl. `chain`, the jump-host route), ssh_config.rs (`preview`: parses ~/.ssh/config with `Include`, first-value-wins `Host` matching, `ProxyJump`/`ssh -W` chains into `Candidate`s keyed by `user@host:port via …`; `Match` is skipped with a note; the engine's `import_ssh_config` re-reads the file, creates jump hosts first and records `profile.import`), secrets.rs (`SecretStore` trait, `GatedStore` (the Touch ID gate); `KeychainStore`/`MigratingStore` remain but the app doesn't use them), vault.rs (`VaultStore`: the credentials file the app uses, ChaCha20-Poly1305, key = SHA-256(per-install key file ‖ hardware UUID)), presence.rs (`UserPresence`; `LocalAuth` on macOS), db.rs (SQLite migrations)
- `src-tauri/`: a thin Tauri 2 command layer (commands.rs) with no business logic. Data lives in `~/Library/Application Support/.orbital` (`DATA_DIR`; on Windows `%LOCALAPPDATA%\Orbital`, see `data_dir`): `orbital.db`, `vault.bin`, `.install-key`. The app never touches the Keychain (each Keychain read prompted, and unsigned rebuilds re-prompt).
- `src/`: the React and TypeScript UI. `lib/api.ts` mirrors the Rust serde types (camelCase). State is in `store.ts` (zustand). Views are in `views/`. Global pages (sidebar foot, `globalView`): Domains (`DomainsView`: accounts/zones/records, `CheckPanel` polls until live), Activity log, Security, Settings. Fixed tabs are Files, Services, Monitor, Terminal and Activity; everything else is a tool tab (`tool:<id>`) opened from the "+" menu in `ServerHeader.tsx`, which lists `detect_tools` results. Dedicated tool views (`TOOL_VIEWS` in `App.tsx`, ids in `DEDICATED_TOOLS`): Docker, Nginx, Apache, HAProxy, PostgreSQL/MySQL/MongoDB (`DatabaseView`), Redis, Firewall (ufw), Fail2ban, Certbot, Sshd, and Ports and Users (`ALWAYS_TOOLS`: offered on every server). Database and web-server views wrap their page in `WithServicePane`, which adds the generic service controls and logs as a second sub-tab. `ToolView` is the generic one. To add a tool, add it to `tools::CATALOG`; to give it its own view, add it to `TOOL_VIEWS`. Theme: colours are CSS variables in `styles.css`, redefined under `:root[data-theme="light"]`; never hard-code a colour in a rule, add a variable. `lib/settings.ts` (zustand, localStorage `orbital.settings`) holds app preferences and sets `data-theme`; Monaco (`orbital-dark`/`orbital-light`) and xterm (`TERM_THEMES`) follow it. Panel widths: `lib/resize.ts` makes the left edge of `.split > .drawer`, `.files > .editor` and the docked editor draggable, storing `--drawer-w`/`--browser-w`/`--dock-w`. UI libraries: Sonner (`components/Toasts.tsx`; call `store.toast()`, not sonner directly), Radix Dialog (inside `Modal` in `components/ui.tsx`), cmdk (`components/CommandMenu.tsx`, ⌘K), NumberFlow (`LiveNumber`). shadcn/ui and Magic UI are not used: they assume Tailwind, and this UI is plain CSS. Floating layers (Toaster, CommandMenu) render outside `.app`, whose grid would otherwise give them a row. Back/forward: `store.ts` records every move (`Loc`: server tab or global page) in `navBack`/`navFwd`; `lib/navigation.ts` adds the swipe, ⌘[ ⌘] and mouse-button triggers, and the sidebar toggle and arrows are `NavButtons` in `Sidebar.tsx`: one fixed group next to the traffic lights, drawn the same whether the sidebar is shown or hidden. Window dragging uses `data-tauri-drag-region` (the `.drag` class's `-webkit-app-region` does nothing in WKWebView). `openFile` and `showFolder` from a tool tab dock beside it (`editorDock`, `folderDock` → `FolderPanel`, rendered by `ToolTab` in `App.tsx`) instead of switching to Files. Saving a connected server's profile calls `profileSaved`; changed connection fields or secrets set `stale` and ask to reconnect (`ReconnectPrompt`). `lib/remote.ts` has `useRemote` (load + reload) and `withSafetyOverride` (on `PreflightFailed`, explain and offer a typed "do it anyway" that retries with `force`). `demo/mock.ts` is a fake backend for `npm run demo`. Profiles have a `protocol` (sftp, ftp, ftps, webdav, webdavs, s3); `isSsh` in `store.ts` gates everything SSH-only (tool tabs, metrics, terminal, chmod, server-to-server copy, validators), and `PRESETS` in `ProfileDialog.tsx` holds the service presets (B2, R2, Nextcloud, …). Deploy, Logs and Tunnels are tool tabs in `ALWAYS_TOOLS`.

## Rules
- The app was called Outpost until 2026-11-15. The old name stays on purpose for migrating users: `OLD_HOMES` in `src-tauri/src/lib.rs` (moves the database from `app.outpost.desktop` / `app.orbital.desktop` into `.orbital`) and `.outpost-bak-*` in `config_edit::list_backups`. Don't rename those.
- Any value interpolated into a remote command must go through `shell::quote`. Identifiers (unit and container names) must also pass `validate_unit` / `validate_container`.
- Secrets never go into SQLite, logs or the audit trail, and never into the Keychain: they go to the vault (`VaultStore`), which must not prompt the user.
- Saved credentials are read only through the engine's `GatedStore`, never the raw store. Any new code path that reads one must first obtain an `Unlock` via `Engine::unlock_for`, and `ssh::saved_secrets_wanted` must stay in sync with the reads in `SshSession::authenticate`.
- A host-key fingerprint is pinned only for the endpoint the user confirmed it for (`ConnectOptions::accept_host`), and a typed secret is used only for the profile it was typed for. A jump-host route never falls back to a direct connection.
- The tool-detection script is built only from `tools::CATALOG`; never interpolate user or server data into it. Tool views don't write configs themselves: edits go through the editor and safe save.
- Anything that can lock the user out (firewall rules, turning ufw on, bans, sshd) needs an engine-side pre-flight check that fails with `PreflightFailed`; the UI may only override it with `force` after a typed confirmation. ufw deletes go by number only after `verify_refs` matched the rule text. Banning the connection's own address is refused with no override.
- Users' crontabs change only through `crontab -u USER -` (it validates), and only after `cron::apply` found the exact line being changed. "Run now" runs only commands that are in a crontab. System cron files are edited in the editor.
- Secrets for the server (new user passwords) go over stdin via `exec_privileged_with`, never into a script or argv; scripts are what gets audited.
- New engine features need unit tests. Anything that touches a server needs a case in `crates/orbital-core/tests/live_ssh.rs`.
- The UI style is slate-blue graphite with a single amber accent (`--amber`), used only for primary actions, selection and live signal. IBM Plex Sans for the UI; JetBrains Mono only for paths, commands, code and the terminal.

## Commands
- `npm install`, `npm run tauri dev` (the app), `npm run demo` (UI with mock data at :1430)
- `cargo test -p orbital-core`, `cargo clippy -p orbital-core --all-targets -- -D warnings`
- `npm run typecheck`, `npm test`, `npm run build`
- Releases: `npm run release -- patch|minor|major|beta|X.Y.Z` (bumps every version, dates `## Unreleased` in CHANGELOG, commits, tags), push the tag, publish the draft. See docs/RELEASING.md
- Live storage tests: `bash scripts/it-storage.sh`, export what it prints, `cargo test -p orbital-core --test live_storage -- --test-threads=1`, then `bash scripts/it-storage.sh stop`
- Live SSH tests: `sudo bash scripts/it-sshd.sh` on Linux/CI, export the printed vars, then `cargo test -p orbital-core --test live_ssh -- --test-threads=1`
